# 通知运行时配置管理指南

本功能用于应用部署后的通知维护。设计合同见[后端设计](runtime-management-design.md)和[页面设计](runtime-management-ui.md)，本地验证结果及限制见[实施验收记录](runtime-management-validation.md)。

## 管理模板

进入“系统设置 → 基础配置 → 通知模板”，按标题、标识、启用状态、来源或默认变化筛选。打开模板可查看当前配置、与部署默认的差异及只读载荷契约。已失去部署默认的历史数据库模板仅供查看。

编辑时可以修改管理标题、启用状态、渠道集合及渠道消息内容和选项。名称和载荷契约保持只读。管理标题可以为空；邮件实际标题由邮件渠道的标题模板控制。添加渠道只列出已安装且提供管理描述的适配器。

“检查配置”不写数据库、不发送消息，也不证明供应商可以连接。确认保存后，原模板表保存整份快照；空值、停用和移除渠道均按保存值生效。后续新发送使用新配置，已有可靠投递计划保留冻结内容。

“撤销覆盖”删除数据库覆盖，随后由原模板中心读取应用文件或 JAR 默认。确认框会展示恢复后的启用状态和渠道，撤销可能重新启用模板。应用升级后，仍存在的覆盖不会自动合并新默认，需要先比较差异；采用新载荷契约需撤销旧覆盖后重新编辑。

出现版本冲突时，本次输入与原版本保留。先读取最新配置，比较“打开时、最新生效、本次输入”，再明确采用最新版本重新检查。出现提交待核对时，先读取最新状态；页面会阻止直接重复保存。网络中断不表示数据库一定没有提交。

## 管理渠道连接参数

“系统设置 → 基础配置 → 通知渠道”目录从已注册适配器生成，不负责安装渠道实现。需要调整连接参数时，进入原配置管理工作台，按目录显示的分组路径定位；该入口要求独立的 `systemSetting.configurationManagement` 权限。通知模板权限为 `systemSetting.notificationTemplate`。

凭据只显示是否已配置，真实值不会回显。留空保留原值，填写新值表示替换；勾选“恢复部署默认配置”后，该项新输入被忽略，并在保存时撤销数据库覆盖。通知渠道的默认值允许为空，撤销后继续随部署默认变化。同组修改和撤销沿原批量事务提交，过期版本返回冲突。

其他组件未声明 `restoreDefaultRemovesOverride=true` 时仍使用其原恢复规则。

## 部署与升级

同一应用可运行多个实例，独立应用使用隔离存储。通知模块沿原 TypedDataModel、配置服务和缓存入口访问，不自建租户字段或命名空间。

多实例的统一配置必须使用原 Spring CacheManager 的共享缓存，例如同一应用隔离后的 Redis 区域。默认进程内缓存只能提供本实例可见性。测试覆盖两个独立 Mothership JVM 通过同一 Redis 保存与撤销的可见性，不能据此声明任意自定义 CacheManager 均具备该能力。所有实例须使用一致的部署默认；滚动升级期间暂停管理写入。

升级前备份原模板表和统一配置值表，在维护窗口停用旧管理写入口。原模型迁移增加模板的 nameKey、revision、默认基线及审计字段；模型初始化后检测历史名称冲突并回填。名称按 Java 忽略大小写规则生成唯一键，实际物理唯一约束与条件写入保护多实例并发。发现冲突时中止并报告，需人工决定保留记录，不自动删除。

统一配置值表新增可空 generation。新行使用 UUID 与递增 revision 组成不透明 token，历史行保持原 token；客户端须原样传回 expectedRevision，不能解析或自增。请勿在新旧版本之间混用管理写入协议。

模板 payloadSchema 和 channel 各限制序列化 UTF-8 字节数不超过 65,535。数据库读取错误会报错，不能作为“没有覆盖”回退默认。缓存驱逐或提交后读取失败可能发生在数据库提交之后，应按提交待核对处理。

### 回退

回退前停止管理写入并备份两张表的当前状态；使用升级前固定提交或已知产物，例如本次基线 `7f9b5b381f9ba1632623299d5ce6172364c5578c`。新增可空列可先保留，无须为代码回退立即删除。旧版本不理解 generation 及本次管理协议，不能与新版并行管理写入；清理本应用所属缓存区域后再启动旧版本。

代码回退不会恢复已撤销的覆盖。是否恢复升级前备份，应先比较升级后实际修改，避免丢失新增业务数据；历史重复记录也必须人工处理。本次只演练旧表样本的向前升级、重启与后续默认版本，没有执行生产回退或自动降级 DDL。

## 验证入口

- Java 行为与持久化：通知 runtime、渠道模块和 configuration runtime 的 `src/test`，包括真实 H2/MySQL、事务、CAS、迁移及共享 Redis 测试。
- 页面：`frontends/web/main-app/tests/integration/notification-runtime-management`，包括生产 AMIS schema 的组件组合及正式 Mothership + 构建主应用的四阶段验收。
- 权限：组件测试使用原元数据 Provider、AuthorityCenter、授权过滤器及评估器；完整应用另验证真实用户名密码登录、正式 RBAC、菜单隐藏、直达页拒绝和 API 拒绝。
- 场景与证据：[回归场景](../../../testing/integration/regression/notification/runtime-management/cases.md)，运行日志保存在 worktree 的 `tmp/testing-evidence/notification-runtime-management/`。

当前不包含真实第三方供应商发送、生产历史数据迁移或部署操作。
