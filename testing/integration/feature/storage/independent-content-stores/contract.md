# 独立内容存储集成契约

## 验证目标

证明公共后端可插拔、消费者实例和生命周期独立；上传/下载走同一消费者实例；文档元数据事务与内容补偿、资源 sidecar 更新由原业务层协调。

## 验证范围与通过条件

- filesystem 与真实 MinIO 同时满足零字节、未知长度、精确长度、失败保留原内容、Range、分页和幂等删除合同。
- 分片乱序与重传按回执合并，重建客户端后续接，重复完成可重试，取消清除技术状态并保留最终内容。
- 相同参数得到两个实例，关闭第一个后第二个仍可读写；SDK 默认凭据链亦独立关闭。
- 上传永久内容立即可下载，同名规则覆盖普通上传/分片完成/临时采用；采用清理失败可重试。
- 开发 JAR 使用完成响应的临时文件 ID 读取内容，不能以会话 ID 代替；JAR/Logo 消费结束或失败均关闭自开流。
- 文档删除与待清理记录同一真实 SQL 事务回滚；提交后故障留下持久责任，新协调器可以重试；共享引用保留。
- 文档上传方法体失败、提交准备失败及回滚补偿失败有行为证据。
- 资源内容成功/sidecar 失败明确报告，恢复默认清除残留 sidecar；损坏 JSON 与后端拒绝不能作为缺失回退。

## 方法

模块行为测试使用真实文件、Spring 装配、真实 H2 数据库与原 SqlDataStation/TypedDataModel/QueryDSL。故障仅注入源流或领域/存储 IO 边界。S3MinioIT 直接调用真实服务，使用独立 bucket 并清理自身对象。

## 失败分类

未提供 endpoint/凭据或服务不可用是环境失败；任何断言、编译、配置装配、权限误判是实现失败。缺少报告或 S3 IT 全部跳过均不能算通过。生产数据迁移与其他厂商真实验收不在本场景结论内。

## 证据要求

保存工作区/分支/基线、运行命令、版本、起止时间与退出码、Surefire XML、JaCoCo XML、Maven 日志。最终报告须区分真实 MinIO、本地 SQL、故障注入与未实测平台。完整 reactor test-compile 与架构门禁另行执行。

## 自动验收入口

`run.sh --base <ref>` 现在串行完成完整 reactor clean 编译、行为回归、架构门禁、覆盖率检查、包结构与实际 JAR 核对。默认基线为本地 `dev-next`；必须解析为当前 HEAD 的祖先，并在执行期间保持不变。源码指纹包含跟踪文件、未忽略新文件、删除状态与执行权限；测试前后源码、HEAD 或基线变化即失败。

行为清单保留原19组必需测试，并动态发现公共存储、上传、资源及文档模块的 `*Test`、`*Tests` 和 `*IT` 文件，包含开发 JAR/Logo 两个消费者回归。发现的新测试自动加入 Maven 选择集；同名歧义、缺少报告、过期报告、零测试、失败、错误、跳过、重复报告、XML计数不符均失败。原必需测试文件消失不会自动减少验收义务。架构模块采用同样的报告校验；覆盖率必须有本轮实际 XML/exec 数据且达到原70%门槛。

`tests/test_verification.py` 通过临时文件与临时 Git 仓库验证上述拒绝行为；`test_storage_verification.py` 是辅助检查器支持的 Python 测试桥接，只调用同一个正式入口，不重写存储断言。具体 JUnit 测试数与桥接测试数分别报告。
