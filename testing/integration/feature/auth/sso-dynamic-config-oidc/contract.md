# 统一认证验收契约

对应组件设计：外部认证配置适配、OIDC 服务端及其授权/配置安全/确认流程/身份资料设计，以及 security 的委托授权和用户资料设计。共同正文入口见[安全设计](../../../../../security/DESIGN.md)和[协议组件设计](../../../../../ability/ouroboros-oidc-server/DESIGN.md)。历史实施报告不作为当前场景或本轮验收结论。

验收使用当前 worktree 构建的 Mothership、主应用生产包和独立数据库/缓存。不得指向用户现有开发或生产数据库。只允许专用测试账号和客户端；HTTP 明文仅限回环地址。使用平台原元数据、模型迁移、权限、配置、缓存、锁及通知接口。

协议链路必须从浏览器平台登录开始，回到 IdP 确认页，再到 RP 回调；实际用授权码与 PKCE 兑换。检查签名、issuer、audience、nonce、过期时间及稳定公开 subject。只请求身份的令牌不能访问平台管理 API。动态注册继续使用同一客户端配置、登录、确认和令牌路径；默认关闭，开放/凭证两种模式均须执行 DCR-01–07。

DCR 配额和凭证并发使用两个真实后端节点、同一 MySQL/Redis。策略锁顺序由独立测试连接和临时数据库触发器控制，仅注入写入等待屏障，所有客户端和策略变更仍经正式 API；结束时删除触发器并恢复关闭策略。数据库故障屏障需要显式指定本场景自有容器，不得对共享数据库执行。

所有敏感值须在落盘前脱敏：平台/OAuth2 令牌、密码、客户端密钥/散列、授权码、验证码、邮件票据、CSRF 和请求关联凭据。证据保留请求方法、路径、参数名称、响应状态、错误码和断言结果。截图不得含密钥框明文；录像仅在截图与请求记录不能证明交互时增加。

可上线判定要求所有适用 case 有 pass 证据、编译与回归通过、新代码覆盖率满足仓库要求、迁移和失败恢复验证通过。未覆盖/失败必须列入报告，不能由组件测试推定系统行为。
