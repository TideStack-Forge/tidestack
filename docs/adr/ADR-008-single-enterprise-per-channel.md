# ADR-008：企业渠道首期各接一个企业

决定状态：Accepted，2026-11-16。

实施情况：每个企业渠道只接一个企业及本期配置为部署级已确认，服务端基数限制及正式界面已实现并有本地测试；单连接入口、自动解析等具体方案在设计正文维护。

替代范围：收窄 [ADR-007](ADR-007-integration-management-workspace.md) 第 1 项对企业渠道保留多连接管理的选择；其上下分区、模块/权限/菜单迁移和插件装配决定保持有效。通用身份源的连接规则不变。

## 背景

当前集成范围以本平台使用企业登录、通讯录、消息、工作台和开放 API 为主。首期钉钉、企业微信、飞书分别只接一个企业，继续为同渠道多企业提供选择器和路由会增加管理员与业务调用方的负担。

## 决定

1. 每个平台部署中，钉钉、企业微信、飞书各最多接入一个企业，三种渠道可以同时启用；不按管理员或业务应用各选不同企业。
2. 管理页按渠道提供一个企业配置入口，首期不提供第二企业新增和多企业选择。一个企业与一个应用保持概念区分；同企业多应用若有实际需求再扩展，不在本次预建。
3. 保留原连接快照及 connectionId，身份关系、业务计划和审计仍引用稳定连接。渠道基数通过原 provider 管理描述声明及服务端校验，不另建默认连接注册表，不任取第一条。
4. 通用 OIDC、LDAP、CAS 身份源及应用接入客户端不受该企业渠道限制。已有多企业配置须先核对引用、显式收口后迁移，不能静默删除或改变业务归属。
5. 本期采用部署级配置。未来租户化由平台统一透明租户方案承接，企业插件、RPC 模型、领域端口和页面不自行添加租户参数或分支；本期不预建租户选择器、作用域开关和每租户连接副本。

## 影响与取舍

通知和 RPC 可按渠道解析唯一连接，业务配置不再反复选择企业；执行上下文及持久记录仍要固定目标，避免配置换企业后旧任务改投。密钥轮换不改变企业/应用身份，更换企业需要新连接及原领域的引用处置。

本决定确认渠道基数和部署级配置，凭据加密、组织同步及通知授权已按方案实现；不表示真实企业联调和发布演练完成。具体方案及剩余实现差距见[企业集成设计](../design/cross-cutting/enterprise-collaboration-integration.md#04-本期企业渠道基数已实现本地验证通过)及其第 6、7、18 节。
