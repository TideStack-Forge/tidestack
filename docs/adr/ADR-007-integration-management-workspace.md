# ADR-007：集成管理按外部连接与应用接入上下分区

决定状态：Accepted，2026-11-15。

后续收窄：第 1 项中企业渠道的多连接管理由 [ADR-008](ADR-008-single-enterprise-per-channel.md) 收窄为钉钉/企微/飞书各接一个企业；通用身份源及其余决定继续有效。

实施情况：名称、首页上下分区、外部连接按类型直接配置、应用接入包含 DCR，以及模块树/权限项/菜单同步调整已确认；界面贡献归集成管理展示层、UI Model 保持通用的职责边界于 2026-11-16 确认。A1 已实现展示宿主及原登录/应用接入/授权服务器/DCR 迁入，企业连接相关页面随共享基础接入。组件和夹具浏览器测试已通过；真实部署授权迁移及完整门禁仍待验证，见模块 README。

替代范围：仅替代 [ADR-006](ADR-006-enterprise-integration-capability-composition.md) 第 5 项中的首页混合对象列表及方向筛选选择；该 ADR 的能力范围、组织关联、RPC 与模块/JAR 装配决定继续有效。

## 背景

外部身份源和企业连接供平台使用外部能力，OAuth2/OIDC 接入应用则使用平台的登录和 API 授权。两类对象的配置、操作和授权语义不同，混排后再筛选增加理解成本。现有入口同时关联 AppModule、菜单、Authority、UI Model、专用配置入口与服务端权限校验，单改页面标题无法完成统一命名与归属调整。

## 决定

1. 管理入口统一命名为“集成管理”；首页上方“外部连接”按供应商/协议类型页签切换并直接配置，下方“应用接入”保留应用列表、授权服务器设置和动态注册 DCR，两区域上下同时展示。外部连接的类型页签来自插件，不把现有多连接模型改成每种类型只能保存一条记录。
2. 模块树、权限项、菜单及相关正式引用同步调整。主菜单保留一个集成管理入口，模块树在其下按两个区域组织能力和权限。
3. 在集成管理展示层定义小型专用管理界面贡献接口，模块的管理界面适配沿现有 SPI/AutoConfiguration 贡献区域、类型/能力位置及已有页面/Schema 的引用；宿主组合两个区域。UI Model 保持通用页面、路由和渲染职责，不通过 extraProps 增加集成语义，也不改造通用路由投影。原领域描述、Schema、菜单及权限机制继续复用，不固定供应商清单，不新建插件运行时。
4. 页面与权限迁移复用原受控机制，保持已有授权范围、字段约束及 Permit/Deny 等语义；能进入主菜单不等于获得所有集成配置的管理权限。
5. 模块树/权限项/菜单同步调整属于已有元数据和授权管理的迁移，不新增“模块与权限”页面或菜单。通知模板就是原多渠道通知模板，内容和渠道选用关系继续由原通知管理入口维护。连接的通知能力页只配置渠道接入参数、展示状态，并可只读展示使用此渠道的模板及按原权限跳转；不保存默认模板、模板白名单或新的连接模板绑定，不新增“通知模板”导航或重复编辑器。测试时选择模板仅用于本次明确授权的测试，不覆盖业务选择。（模板与连接职责于 2026-11-16 澄清。）

### 2026-11-16：界面装配的职责边界

区域、连接类型和能力归属是集成管理自己的展示规则。即使 UI Model 支持扩展属性，也不应由通用页面模型承担这些专用约定。界面组合留在集成管理展示层，原 UI 机制按引用提供页面和渲染能力。

专用贡献接口已实现为展示层的 `IntegrationManagementContributor/IntegrationManagementPage`；契约由宿主与管理界面适配依赖，业务 core、供应商协议基础和通用 UI 模块不依赖它或宿主实现。它不替代原 provider/channel/RPC 发现，不复制业务能力、配置或启用状态；读写、校验和操作仍调用原领域接口。装配沿现有 SPI/AutoConfiguration，不增加插件安装表、可变全局 Registry 或生命周期框架，JAR 粒度以最小装配需要为准。

第 7 轮后续确认分区独立授权/加载、逐 key 单一编辑链路、Schema 与受控数据分离，以及菜单和领域权限的独立归属。两区不能共同依赖客户端列表权限；授权服务器设置连同外部登录及 DCR 完整迁入；保存沿原管理策略和 CAS 保全其他对象。匿名 Schema 只返回安全页面结构，业务数据仍从受控接口加载。根菜单由宿主贡献，领域权限仍由所属模块维护，不由页面位置授予。

第 7 轮架构建议均已确认；贡献合同、页面及本地迁移行为已有实现；真实部署迁移待验。合同边界与验证要求见设计正文 §9.4.1–§9.5、§13.1。

## 影响与取舍

整合发生在管理入口与组织结构，各领域继续拥有自己的配置和操作。已有角色授权和权限引用须随正式标识迁移，原配置键、客户端身份和领域 API 不为入口改名而重新创建。旧页面只导航到新入口，切换后使用单一权限及编辑链路。

具体目标标识、迁移清单与验收要求由[企业协作平台集成设计 §9](../design/cross-cutting/enterprise-collaboration-integration.md#9-配置校验与生效)维护；详情页交互继续在该正文讨论。

凭据、目录、通知/RPC 和插件装配的实现进展及剩余验收差距见[实施前待补合同](../design/cross-cutting/enterprise-collaboration-integration.md#18-实施前待补合同)，不以本 ADR 的 Accepted 状态推定完成。
