# 并行协作规范

## 修改归属

每个任务先声明目标分支/worktree、文件范围、共享接口与集成责任。重叠文件由相关任务先确定唯一编辑归属和共同契约；依赖任务按已确认接口推进。共享Registry、SPI、Schema或配置变化在关联任务/MR记录并通知依赖任务，禁止各自维护第二份定义。

独立任务使用独立分支/worktree。同一工作区只有任务明确协调、无并发写入同一文件且可区分暂存归属时才共享；不重置或替其他任务提交。集成责任由承担组合交付的任务明确接下，不能从提交作者猜测负责人。

## 工作区与共享资源

| 资源 | 隔离与归属 | 允许共享的条件 |
| --- | --- | --- |
| worktree | .worktrees/下使用任务稳定名称；命令显式workdir | 协调编辑范围与暂存归属，不覆盖别人未提交工作 |
| 端口与进程 | 任务记录服务URL、端口、启动命令、PID/日志和所有者 | 明确服务版本、只读/写入范围和生命周期，使用者不得杀他人进程 |
| 数据库 | 使用场景独立库/夹具，记录初始化与清理边界 | 写入同一库前确认数据命名/隔离、备份与清理归属；禁止清空共享库 |
| 缓存/队列 | 按环境/任务使用namespace、前缀或独立实例 | 键、队列和消费组不冲突；只清本任务拥有的数据 |
| 构建输出 | 各worktree使用自身target/dist/tmp；保留复现必要产物 | Maven本地缓存可共享但不并发安装同坐标的不同未发布版本；需要时用任务独立本地仓库 |
| Docker/集群 | 记录容器、卷、namespace与实际后端 | 不按通用名称停止/删除共享资源；结束先确认其他消费者 |

## 交接与组合验证

在关联任务或MR交接来源HEAD/提交、修改范围、接口与迁移影响、已运行/失败/跳过验证、未决项及保留资源。未提交工作提供可恢复补丁/快照和文件归属；不要声称只有口头“已做完”即可集成。

按正式合同/Schema → 提供者 → 消费者/装配 → 用户旅程的依赖顺序集成。组合任务依据 [测试规范](testing.md)选择受影响模块、testing场景和关键旅程；每个任务单独通过不能替代合并后的组合验证。冲突在当前设计内解决，不通过保留两条行为链绕过。

## 回收

先检查git status、暂存区、未推送提交及任务附件，确认所需提交已集成或另有可恢复去向。对被忽略的日志、截图、数据库或生成物单独确认需要保留的部分与存放位置，Git快照不自动包含它们。

只回收自己拥有的进程、数据、容器和工作区。共享资源先交接实际接收方与保留时限，再移交维护；没有接收方且仍被依赖时保留并报告。回收分支方式遵循 [版本规则](version-control.md)。
