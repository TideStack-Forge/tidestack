# 文档治理规范

本规则适用于根入口、docs、模块文档、项目维护Skill及其资源。普通修订历史由Git维护，字段只按实际识别与工具需求保留。

## docs 准入边界

docs/ 及其全部子目录只保留反映最新情况、需要持续维护的长生命周期文档。正文说明当前能力、有效需求、设计与契约、规则、操作方法及尚未解决的风险；代码或决定变化时更新原正文，已确认但未实现的内容明确标注差距。

研究记录、讨论草稿、评审意见、任务执行计划、实施日志、阶段总结、单次测试或验收报告、rebase 与发版操作记录均属于过程文档，不得进入 docs/。不得通过放入 docs/archive/、追加日期章节或改名为设计文档来保留这些记录。

面向使用者的操作流程、可重复执行的验证方法和故障排查步骤属于长期知识，可以保留；某次任务执行了哪些步骤、产生了哪些结果，归对应任务。ADR 只承载仍有长期解释价值的决定依据及最新有效或替代状态，不承载评审讨论和实施流水账。

## 职责与正文归属

| 位置 | 维护内容 | 更新依据 |
| --- | --- | --- |
| docs/features | 已实现能力、限制、启用条件及代码入口 | 当前源码/配置，运行和发布另取实际证据 |
| docs/requirements | 已确认的业务目标、场景、约束与验收 | 有效规格及明确决定，不反向迁就实现 |
| docs/design与模块DESIGN/docs | 机制、生命周期、状态/并发/失败处理、扩展点及取舍 | 当前设计与已采纳决定，超前部分就地标明差距 |
| docs/api | 正式HTTP合同入口、权威输入与派生方向 | WebAPIModel源定义及正式导出；不手改生成结果 |
| docs/adr | 重要决定的长期依据、选择、后果与当前替代关系 | 全仓唯一递增编号，维护最新决定状态，实施差距同步当前设计 |
| GLOSSARY.md | 项目专有概念、规范称呼与歧义边界 | 唯一领域定义，行为和机制转需求/设计 |
| docs/rules | 需要统一执行的项目取舍与使用边界 | 正式约定、适用范围及真实工程入口 |
| docs/handbook | 面向使用者的产品与操作说明 | 实际交付版本、开放范围与站点规则 |
| .agents/skills | 复杂可复用操作的任务入口 | 复用正式工具和唯一步骤资源，不另写实现 |

docs/README只导航非规则知识。AGENTS直接保留执行纪律并逐主题链接规则及读取时机，不复制技术版本表、不建立Skills清单。局部AGENTS仅补真实差异。

## 主题准入与按需阅读

新增前先找稳定主题，能承载则更新原正文。只有职责长期独立、边界明确且已有主题无法承载时才新增。功能树、需求树和设计树按各自语义组织，不强求与物理模块一一对应。

叶子用单文件，有独立子主题再设目录README。总览只保留概述、边界、关系和导航，细节在具体主题。模块README说明概况，模块DESIGN说明局部机制，中央摘要引用唯一正文。写作模板独立保存，只在相关索引的写作辅助区单列，不计入功能/需求/设计现状。

当前正文采用稳定英文小写连字符名称，持续原地更新；日期仅按决定时点、来源版本等长期识别需要保留，不按每次任务复制当前规格或追加执行记录。沿用必要的ADR历史编号和模块固定文件名。

## 资料与过程

外部资料只在具体需求/设计需要核对来源时引用，保留原始来源、版本/核对日期及采用关系；任何层级README/AGENTS不导航资料目录或建立资料索引。资料本身不直接成为项目规则。

研究、评审、计划和单次验证归关联任务、PR 或 Issue。本地任务记录可保存在已忽略的 `.codestable/work/`，一次性验收报告、日志、截图和构建物默认归 `tmp/testing-evidence/`。`.codestable/` 全目录及上述执行记录均不得进入版本库。需要长期追溯的证据在清理前保存到 CI 或任务指定存储，注明访问与保留条件。任务没有平台时，用该次交付说明或附件保留。

长期结论回写对应正文，未闭合风险/债务在docs/risk-tracker.md、docs/tech-debt-tracker.md原条目更新，条目只保留当前问题、影响与处置要求。正式正文不得依赖 tmp/、target/ 等本地临时产物链接；确需引用验证依据时，使用长期可访问的任务或CI制品地址，标明适用提交与验证范围。只有本地证据时，在交付说明中提供位置和保存边界。

发现已有过程文档混入 docs/ 时，先将仍有效的长期结论并入对应正文，再将过程记录保留到关联任务、附件或固定Git提交，移出 docs/ 并同步修正索引与入链；不在 docs/ 内建立历史归档目录。

设计与能力现状分别更新 `docs/design/` 和 `docs/features/` 的唯一正文，保留已确认要求、方案取舍及当前实现差距。需求归 `docs/requirements/`。现有模块深入设计通过中央设计索引接入，迁移时同步入链与权威正文归属。

已入库的过程材料停止跟踪后，可通过原 Git 提交追溯。仍被工程消费的长期输入先迁到正式工具目录并同步消费者。依赖策略由 `scripts/ci/dependency-policy.yaml` 维护，开源导出与同步清单由 `scripts/open-source/manifests/` 维护，单次运行输出归 `tmp/testing-evidence/`。这些长期输入只保存有效契约与约束，执行日志及历史验收报告归任务附件。

## 更新与替代

先明确当前正文和适用基线，再同步相关功能、需求、设计、契约、术语与操作说明。代码事实与已确认需求冲突时保留差距，提问题或修实现，不改需求伪装通过。

移动前找入链、锚点及实际读取工具；移动后同时改父索引、模块入口和引用。当前正文择一维护，旧文退出默认阅读链。确有工具/外部稳定引用依赖时，旧入口只保留指向唯一正文的跳转，并注明删除条件，不留第二份完整正文。

设计决定改变时更新当前设计，并按重要性用新ADR表达长期理由、同步原决定的替代状态。历史讨论和评审只保留在关联任务或Git历史中，不能作为当前代码基线。未采纳方案留关联任务，不进入 docs/；已采纳但未实施的设计在当前正文标明差距，不计入已实现能力。

## 检查与交付

更新后回读diff、正文、示例、图表及源类型，检查是否混入过程记录、是否反映最新情况，以及事实、相对链接、标题锚点、模板占位和正文唯一性。正式链接检查命令为仓库根目录的 bash scripts/docs/check-links.sh；其扫描排除handbook、.codestable、work及依赖/构建目录，不能据此称全部链接通过。

handbook当前按用户要求冻结，不运行安装、生成或构建；未来解冻后再按其package命令校验。前端规则链按frontends/web的validate:agent-entrypoints检查。文档质量脚本采用docs/design规则。安全、认证、授权资料与其他主题共同维护正文和入链；handbook继续冻结，不改动站点正文、配置或生成文件。

每次验证记录提交、环境、命令、场景、时间、实际结果与排除范围。说明未执行/阻塞和证据保存位置，禁止虚构负责人、支持期限、许可或运行通过。
