# 企业集成验收与发布核对

适用于钉钉、企业微信、飞书自建应用，以及集成管理的配置和权限迁移。每渠道在同一部署最多一个企业连接。本次交付按用户确认，用仿真外部服务验证内部机制；真实企业及存量部署差异保留为发布核对，不阻塞本次仿真验收。各层证据见[方案 §15.1](../design/cross-cutting/enterprise-collaboration-integration.md#151-本地验证与发布待验)。

## 本次仿真验收

可重复运行的[场景契约](../../testing/integration/feature/enterprise-integration/simulated-platforms/contract.md)和[用例](../../testing/integration/feature/enterprise-integration/simulated-platforms/cases.md)覆盖三家登录/绑定、分页目录、通知、RPC、统一业务回调，以及权限、停用、跨节点轮换、数据库中断、主密钥重加密和重启恢复。使用两个正式 Mothership 节点及专用 MySQL 8.3、Redis 7，保留原认证、配置、事务和领域服务；仿真只替换外部 HTTPS 服务，不向生产代码加入测试接口或备用端点。

在该 worktree 根目录执行，前提和构建要求以场景契约为准：

```sh
python3 testing/integration/feature/enterprise-integration/simulated-platforms/scripts/run.py \
  --root tmp/enterprise-integration/simulation-acceptance
```

根目录必须尚不存在。runner 结束时清理归属匹配的自有容器、网络和网关；失败也执行清理。`tmp/testing-evidence/enterprise-simulation/summary.json` 只有全部阶段及清理通过才标记 `pass`，阶段日志、持久化观察及浏览器截图保存在同一目录。仿真通过证明被测内部链路，不代表供应商认证、真实客户端行为或存量生产迁移通过。

以下为接入真实企业、执行实际发布前的待核对清单。

## 开始前准备

只在指定的测试部署和测试企业执行；发消息及写 API 会产生真实业务效果。先明确测试收件人、可见目录、测试业务对象和清理负责人。密钥通过管理页或正式凭据引用配置，不写进验收记录、脚本参数、截图或日志。

| 条件 | 需要提供或核对的内容 |
|---|---|
| 部署 | 测试平台地址、构件版本、数据库/缓存位置、节点数；所有节点相同的托管凭据主密钥 key ring |
| 企业应用 | 每个渠道的自建应用、企业/应用标识、已批准 scope、通讯录可见范围及字段权限；凭据通过受保护渠道交接 |
| 网络与入口 | 公开 HTTPS 地址、企业后台授权回调白名单；业务回调采用连接页提供的 `/api/enterprise-callbacks/{connectionId}/callback`，OAuth 回调沿原安全入口，不能互换 |
| 身份和通知 | 测试平台账号、企业成员、本地员工及关系核对人；至少一个受限管理员和一个允许接收测试通知的当前管理员 |
| 执行预算 | 依据实际 API 配额设置 `enterprise.api-budgets`；按真实执行节点设置 `ouroboros.enterprise.execution-nodes`，不让每节点各用完整预算 |
| 迁移和回退 | 本次涉及的旧角色/范围、配置版本、通知地址和在途业务清单；备份、维护窗口及上一版构件 |

没有真实企业、scope、公开地址或测试账号时，对应项目记为待验并保持相关生产能力关闭；不新增代码中的证据状态或统一激活流程。

## 按能力验证

先在隔离测试部署保存最小配置，再分别启用拟验收的能力。连接诊断目前只允许已保存且已启用的连接；诊断成功不代替下面的业务验收。

| 项目 | 操作及可观察结果 | 失败时如何处理 |
|---|---|---|
| 连接和凭据 | 从集成管理上方保存自建应用连接及调用预算；“检查已保存连接”显示对象、时间和应用令牌检查范围，响应无密钥/令牌。当前未保存草稿不被提交 | 核对凭据、主密钥、预算和网络，保留安全错误摘要；不把失败自动改成全连接停用 |
| 登录与解绑 | 从真实企业客户端授权；未绑定时输入平台账号密码，成功后进入原目标。管理员在原用户详情查看/解绑后，旧登录绑定不能恢复，组织关联不被级联删除 | 核对外部稳定身份、企业归属、redirect URI 和绑定冲突，由管理员人工处理，不自动猜测新旧账号关系 |
| 目录绑定与同步 | 先绑定现有部门/员工，再预览选定范围的单向同步；多渠道关联同一员工时只有一个主来源，分页失败不能应用部分快照，无 User/角色自动新增 | 校验企业可见范围和字段权限；缺失成员先核对，不直接当作离职或全量删除 |
| 通知 | 在原多渠道模板中选渠道；企业接入测试仅向当前管理员已关联成员发送固定测试内容。业务发送验证原披露权限、固定连接及失败恢复 | 结果未知的写请求先核对远端，不直接重发；无 User 员工不绕过原业务内容授权 |
| 工作台 | 从管理页生成站内目标链接，在企业工作台手工配置；真实客户端进入后完成认证/绑定并恢复目标，原业务访问权限继续生效 | 区分授权失败、未绑定和无业务权限；不开放任意外部回跳地址 |
| RPC | 从“企业开放 API”跳到原 RPC 管理，按已装 JAR 查看接口。只读接口先验参数、目标和 scope；有真实写效果的测试明确目标后再执行 | 检查原管理与企业调用两项权限、唯一连接及令牌位置；普通参数不能替换连接或最终目标 |
| 业务回调与审批 | 企业后台完成 challenge，发送已订阅审批事件，收到合法 ACK；重投不重复业务事实，部分订阅未受理时不得成功确认。审批映射仍走原校验/激活 | 保留脱敏事件身份与领域事实，按原 receipt/inbox 恢复。没有业务订阅不等于已完成审批集成；详见[审批发布清单](approval-workflow-external-integration-release-checklist.md) |
| 权限与停用 | 受限管理员直接请求无权操作应被拒绝；应用范围管理员不获得全局连接权限。取消停用无写入，确认后新调用拒绝，历史保留 | 管理员处置在途通知/审批及供应商后台；不承诺自动收尾或重新启用后批准补发 |

## 迁移与多节点演练

1. 按[集成管理模块说明](../../ability/ouroboros-integration-management/README.md#权限和旧入口迁移)在维护窗口执行权限等价改名。先停止旧节点并备份，在维护实例显式启用迁移；核对范围、字段限制、Permit/Deny、DCR 来源和凭证状态。失败停止切换，不保留双编辑入口或旧权限永久别名。
2. 按[企业连接基础](../../ability/ouroboros-enterprise-connector/README.md#业务回调)停止旧回调地址投递，保留领域事实，切换企业后台的新地址并确认受理。同一事件不要同时投递新旧入口；旧钉钉专属 receipt 表不自动删除。
3. 启动实际数量的执行节点，演练应用密钥轮换、停用及数据库不可读。新调用应复核权威版本或明确失败；旧刷新晚到不覆盖新代次，令牌不串用。主密钥轮换另按模块说明保留新旧 key ring 并验证恢复。
4. 核对各节点总调用速率、通知/审批积压及目录/通知内容清理。预算不足不能发出请求，结果未知的写请求不普通重放；清理保留恢复和幂等事实。记录实际恢复耗时及未恢复数据。
5. 需要回退时停止新节点与相关写入，恢复相应构件/数据并核对供应商入口，不能假定旧程序可直接读新配置。回退不能撤销外部请求或恢复已撤销凭据。

这些步骤尚未在真实部署执行。专用库和两个正式进程的仿真演练已有对应场景；其结果不代表存量生产数据迁移、真实节点运维或生产回退已验收。

## 保存验收记录

每项记录环境/构件版本、时间、操作者、渠道及脱敏 connectionId、已批准 scope、期望与实际结果、关联事件/任务 ID、证据位置和清理结果。失败或缺少条件明确保留待验原因，不使用“未发现问题”代替实际执行。

逐项通过后才开放该能力的生产入口；无需因为某项未验而关闭其他已独立验收的能力。验收结果保存在方案或发布记录，不增加连接状态枚举、数据库字段或运行开关。
