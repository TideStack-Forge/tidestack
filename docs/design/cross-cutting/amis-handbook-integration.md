# AMIS 与 Handbook 文档集成设计

状态：集成提案。当前只提供 handbook 导读与外链，尚未交付上游镜像或运行时沙箱。

## 背景

外部 AMIS checkout 的 `docs/zh-CN`（本地工作副本示例：`~/Projects/amis/docs/zh-CN`）提供 AMIS 原生文档，覆盖快速开始、核心概念、组件、类型、样式和扩展机制。当前 handbook 已经有面向潮汐栈开发者的 UI Schema、前端 API、SDK、组件库和微前端文档，但 AMIS 原生能力与平台能力之间仍然缺少一个完整、可运行、可搜索的文档体验。

这份文档记录 AMIS 文档与 handbook 的集成设计。它属于内部设计资料，不直接放进 handbook。handbook 面向开发者呈现的是最终可用的入口、路线判断和参考索引。

## 目标

- 让平台开发者能在同一套文档体验里理解 AMIS 原生能力和潮汐栈平台能力。
- 保留 AMIS 文档中的可运行沙箱体验，尤其是 `schema:` 示例。
- 明确 handbook、AMIS 原生文档和平台 API 文档的职责边界。
- 让 AMIS 上游文档同步可重复，避免人工复制导致漂移。

## 非目标

- 不在 handbook 用户手册正文里暴露“集成方案”或内部实施细节。
- 不重写 AMIS 原生组件、属性、事件动作和表达式文档。
- 不把 AMIS 上游文档直接揉进低代码教程正文。
- 不在没有沙箱能力的情况下宣称 AMIS 文档已经完整集成。

## 当前文档职责边界

| 文档来源 | 主要职责 | 不应该承担 |
| --- | --- | --- |
| handbook | 平台路线判断、潮汐栈能力导读、SDK 与内建组件、组件库和微前端接入方式 | 逐项重写 AMIS 原生组件属性 |
| AMIS 文档 | AMIS 原生概念、组件属性、事件动作、表达式、数据映射、样式与扩展参考 | 解释潮汐栈里的页面入口、权限、菜单、SDK 和扩展治理 |
| docs/design | 集成设计、边界、风险和验证策略 | 面向最终开发者的使用指南 |

集成后的开发者阅读路径应该是：

1. 先在 handbook 判断当前问题属于低代码页面、UI Schema、组件库还是微前端。
2. 如果要写或调试 Schema，再进入 AMIS 原生参考库查组件和语法。
3. 如果要调用平台能力，再回到 handbook 的前端 API、SDK 和基座内建组件文档。

## 推荐信息架构

handbook 中保留一个面向开发者的 AMIS 入口页，负责路线判断和入口索引；内部设计保留在 `docs/design/`；执行计划、同步试验和验收记录归关联任务附件。

推荐最终形态：

```text
docs/handbook/docs/guide/advance/amis-reference/
├── index.md
└── upstream/
    ├── index.md
    ├── start/
    ├── concepts/
    ├── components/
    ├── types/
    ├── style/
    └── extend/
```

其中：

- `index.md`：面向平台开发者的最终入口，帮助判断该看 AMIS 原生文档还是潮汐栈平台文档。
- `upstream/`：同步 `~/Projects/amis/docs/zh-CN` 的原始参考内容。
- 平台补充说明不直接写入 `upstream/`，避免和上游同步冲突。

## 沙箱能力约束

AMIS 文档不是纯静态 Markdown。当前 AMIS 文档里有大量这种代码块：

````text
```schema: scope="body"
{
  "type": "page",
  "body": "Hello AMIS"
}
```
````

在 AMIS 原始文档构建链路里，这类代码块会被 Markdown 预处理转换成可渲染的预览结构：

```html
<div class="amis-preview">
  <script type="text/schema" scope="body">
    ...
  </script>
</div>
```

因此 AMIS 文档正式接入 handbook 时，必须同时接入对应的渲染能力：

- 识别 `schema` / `schema:` 代码块及其 `scope`、`height` 等属性。
- 将代码块转换成可运行的 AMIS 预览容器，而不是普通代码高亮。
- 在页面运行时加载 AMIS 渲染器、样式和必要的 mock API / env 适配。
- 对外链、下载、接口请求、iframe、HTML 示例做安全边界处理。

如果短期不能实现运行时沙箱，AMIS 文档只能作为外链或只读参考接入，不应标记为“完整集成”。

## 可选落地路径

### 路径一：外链保底

handbook 只保留平台导读和阅读路径，AMIS 原生内容继续跳转到官方或本地 AMIS 文档站。

优点：

- 成本最低。
- 不需要维护 AMIS 沙箱运行时。
- 不会引入大量上游文档同步问题。

缺点：

- 搜索体验被拆开。
- 平台开发者在 handbook 和 AMIS 站之间来回切换。
- 无法在一个站点里形成完整学习路径。

适合作为第一阶段保底方案。

### 路径二：静态镜像 + 沙箱增强

把 `~/Projects/amis/docs/zh-CN` 同步到 handbook 的 `amis-reference/upstream/`，并为 Docusaurus 增加 AMIS Markdown 转换和运行时渲染能力。

优点：

- handbook 内搜索可以覆盖 AMIS 原生文档。
- 平台导读和原生参考在同一个文档站里闭环。
- 保留 AMIS 示例的可运行体验。

缺点：

- 需要维护 Markdown 转换插件。
- 需要处理 AMIS 样式、运行时依赖和 mock API。
- 构建体积和页面性能需要额外控制。

这是推荐的正式集成路径。

### 路径三：双站点组合

handbook 作为主站，AMIS 文档保持独立构建，通过导航、搜索索引或反向代理组合成统一入口。

优点：

- AMIS 原始文档构建链路改动最少。
- 沙箱能力可以继续沿用 AMIS 自己的实现。
- 上游同步成本低。

缺点：

- 站点体验仍然有割裂感。
- 搜索、权限、部署和版本切换需要额外整合。
- 平台语境和 AMIS 原生语境之间仍需大量交叉链接。

适合已有独立 AMIS 文档服务时采用。

## 同步规则

AMIS 上游文档同步应保持可重复，不建议人工复制单篇文档。

建议规则：

- 以选定版本的 AMIS checkout 中的 `docs/zh-CN` 为同步源；本地绝对目录只是工作副本位置，不是仓库前置条件。
- 忽略 `.DS_Store`、临时文件和非中文文档。
- 保留原始目录结构，方便后续 diff。
- 同步后运行链接检查和 `schema:` 代码块统计。
- 平台补充内容不要直接写进 `upstream/`，避免和上游同步冲突。

## 技术风险

| 风险 | 影响 | 处理建议 |
| --- | --- | --- |
| `schema:` 代码块无法渲染 | AMIS 文档体验明显降级 | 正式集成前必须实现沙箱渲染或保持外链 |
| 示例接口依赖 mock 数据 | 预览失败或行为不完整 | 提供 handbook 专用 mock/env 适配 |
| 外链和相对路径不兼容 | 页面跳转失败 | 同步后做链接转换和 broken link 检查 |
| AMIS 样式影响 handbook | 全站样式污染 | 将预览运行时隔离在专用容器，必要时 iframe 化 |
| 文档体积过大 | 构建和搜索变慢 | 分阶段接入，组件页可先按需同步 |
| 上游文档频繁变化 | 维护成本上升 | 使用脚本同步，平台补充内容独立存放 |

## 不建议的做法

- 不建议把 AMIS 文档内容直接揉进平台教程正文。
- 不建议把 `schema:` 代码块当普通 `json` 代码块处理。
- 不建议在 `upstream/` 里直接修改上游文档语义。
- 不建议一开始就重写 AMIS 文档信息架构。
- 不建议用 handbook 替代 AMIS 官方或上游文档的原生参考职责。

## 当前状态

handbook 的 `AMIS 开发参考` 提供路线导读和外部参考入口；当前没有 `upstream/` 镜像目录或沙箱渲染链路。后续若采纳正式内嵌方案，在关联任务中安排同步、沙箱和验收工作，不能把本提案视为已经交付的能力。
