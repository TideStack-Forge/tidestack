# 模块设计摘要模板

## 模块定位

说明模块在平台中的定位、面向的主要维护者问题，以及它属于哪个顶层模块群。

## 责任边界

说明模块负责什么、不负责什么，以及它与同层或相邻层模块的边界。

## 依赖关系

概述模块主要依赖下层哪些稳定能力、被哪些上层模块消费，以及需要维护者特别关注的边界约束。

## 关键抽象

列出模块最值得维护者先理解的核心概念、对象、协议或运行时抽象，避免在摘要页展开实现细节。

## 关键子模块

按维护视角列出关键子模块或子包分工，只保留帮助建立结构认知的最小信息。

## 扩展机制

只保留简短机制摘要：说明模块使用了哪类扩展机制、典型入口位于何处、为什么需要它。若机制属于共享约定，应链接到跨模块专题而不是在本页重复展开。

## 当前正文与依赖

导航到当前机制、正式契约和可复用操作入口，说明每个链接的职责。模块 DESIGN 是详细机制的共同正文，中央摘要只说明边界与阅读顺序；同一设计不按模型或作者建立副本。

已接受但未实现的机制就地说明差距。单次研究、评审、计划和验证材料归关联任务、PR 或 Issue，有效结论回写当前正文，未闭合事项在风险/技术债台账跟踪。重要长期取舍可链接唯一 ADR，不在当前索引建立历史资料书架。

## 实现差距

仅列与本主题相关的真实差距、影响和对应台账入口。没有独立深度文档时直接说明，不生成空文或未知负责人占位。
