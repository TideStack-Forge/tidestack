# 在开发平台里管理应用运行时

## 用户故事

- 作为开发平台维护者，我希望为某个应用和环境直接拉起测试运行时，而不是自己拼镜像、端口和启动顺序。
- 作为联调中的开发者，我希望在一个入口里看到运行时是否可用、该怎么访问、能不能重载或回收，而不是去底层平台逐个找对象。
- 作为处理环境问题的人，我希望清理残留运行时、切换基础镜像或打开临时调试接入时，平台给我统一入口，而不是每次手工执行一串命令。

## 为什么需要

开发阶段最容易浪费时间的，不是改业务逻辑，而是把“这套环境到底有没有起来、现在该连哪里、上一次留下来的残留有没有影响”这些问题反复确认。底层运行时可能来自 Docker，也可能来自 Kubernetes；如果没有统一管理入口，维护者就得自己记容器、端口、镜像和环境差异，联调成本会一路放大。

## 怎么解决

开发平台提供一条统一的运行时管理流程，让维护者围绕“某个应用在某个环境下的运行时实例”来操作：创建、查看状态、调整镜像、进入访问入口、重载工作区、删除残留实例，以及按需要申请临时调试接入。这样使用者面对的是稳定的管理语义，而不是底层基础设施细节。

## 边界

- 它不负责生产部署、正式发布编排或长期运维治理；它服务的是开发阶段和联调阶段的运行时管理。
- 它不把底层 Docker 容器 ID、宿主机端口或 Kubernetes Pod 当成主要管理对象；必要时可以展示细节，但不会要求维护者直接围绕这些对象工作。
- 使用前提是目标应用已经存在，且当前环境具备可用的运行时基础设施与相应管理权限。
