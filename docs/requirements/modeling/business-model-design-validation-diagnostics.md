# 业务模型设计时直接看到校验问题

## 用户故事

- 作为业务模型设计人员，我希望在模型列表里直接看出哪些模型存在校验问题，而不是逐个打开或等发布后才发现。
- 作为正在编辑模型的人，我希望打开和保存后立刻看到当前模型的校验错误，而不是从投射失败或运行时报错里反推原因。
- 作为处理模型关系的人，我希望关系引用类问题也能出现在同一处诊断里，而不是在多个页面和日志之间来回找线索。

## 为什么需要

业务模型是低代码应用的核心定义之一。模型定义一旦有字段、关系或类型层面的错误，后续投射、页面生成和运行时能力都会受影响。如果这些问题只能在发布或运行后暴露，维护者就会在更晚、更难定位的阶段返工。

## 怎么解决

在业务模型的设计入口直接展示后端校验结果：列表页先提示哪些模型有问题，编辑页在打开和保存后展示当前错误摘要和明细。基础提交错误仍然阻断保存；模型语义问题先作为设计诊断可见，让维护者能保存草稿并继续修正。

## 边界

- 不新增业务模型校验规则，只展示系统已经能判断出的设计时问题。
- 不负责字段级高亮、自动跳转到具体配置项，或从错误文案反推出字段路径。
- 不替代发布、投射或运行时校验，也不决定模型是否启用或参与运行时选择。
- 不把诊断信息当作业务模型定义的一部分持久化。
